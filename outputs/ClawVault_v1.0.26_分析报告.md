# ClawVault 项目现状分析（v1.0.25 基准 → v1.0.26）

本文档基于源码、已部署实例（飞牛 fnOS / 192.168.192.46:5666）和真实回归测试编写，
所有结论都能在 `git log` 或测试用例里追到证据。

---

## 一、做得好的地方

### 1.1 架构清晰
- `providers/` 抽象出 7 种 Bot 接入（微信 iLink / Webhook / Telegram / 钉钉飞书企微 / Discord-Slack / filedrop / office），
  `ChannelManager` 是与具体平台无关的泛型，扩展新平台只需写一个适配器。
- 存储层 `Storage` 是单一数据出口：SQLite 元数据 + 飞牛文件系统落盘，关注点切得很干净。
- `app/ui/config` / `cmd/main` / `config/privilege` / `config/resource` / `manifest` 是飞牛原生的"五件套"，是踩过 v1.0.3~v1.0.9 一连串 fpk 启动失败后沉淀出来的标准布局。
- 媒体链路完整：iLink AES-128-ECB 解密 → 真实文件头判定扩展名 → SILK/AMR/WAV/MP3/OGG 转码 → SHA-256 同通道去重 → jimp 缩略图 → Range 流式播放。

### 1.2 安全基线
- 媒体/语音路由都有路径穿越防护，并显式校验 `path.resolve(archiveRoot, m.media)` 仍落在归档根内。
- 通道凭据用 `vault.js` 加密落盘（AES 主密钥，优先级 `CLV_MASTER_KEY` > `data_dir/.clvkey`，mode 0600）。
- 设置接口的 API Key 走 `******` 掩码返回（但本版发现 POST 端有回写 bug，已修，详见下文）。
- 不信任客户端自带的用户 ID，只认网关注入的 `X-Trim-Userid` / `X-Trim-Isadmin` / `X-Trim-Username`。

### 1.3 飞牛打包的"踩坑笔记"非常成熟
- `checkport=false`（Unix Socket 不监听 TCP 端口）、`type:"url"` 入口、`url` 带尾斜杠、`desktop_uidir` 清空。
- `cmd/main` 自动探测 `/vol1/@appcenter`（兼容控制目录 /var/apps 异常）、
  用 `__dirname` 推导 `public` 而非 `process.cwd()`。
- 运行时可写数据（log / pid / db / settings）写 data-share 目录，绕开安装目录 root 属主。
- `.gitattributes` 强制 LF、`prepare-runtime.sh` 校验 ELF 头、`runtime/sqlite3-pristine/` 自愈备份。
- fpk 校验脚本 `--check` 模拟双层解压、验证 ELF 头、防止 LICENSE 漏到外层触发自动协议步骤。

### 1.4 体验细节
- 深色模式（语义化 CSS 变量、localStorage 记忆、跟随系统）。
- 移动端响应式（≤768px 折叠为单栏 + 抽屉）。
- WebSocket 单例重连守卫。
- jimp 缩略图（降低列表带宽）。
- 无障碍：focus-visible、aria-pressed/expanded、`role="button"`。
- WCAG 2.2 AA 对比度（`--c-muted` 经测算 ~4.6:1）。
- 测试覆盖 70 个用例（含本次新增 6 条回归测试）。

## 二、需修复的缺陷（按严重度）

### P0 — 功能性 / 数据正确性

| # | 缺陷 | 影响 | 本版状态 |
|---|------|------|----------|
| 1 | **类型筛选完全失效**：`routes/messages.js` 解构了 `kind` 但没透传给 `storage.listMessages()`，前端"文本/语音/图片/表情/视频/文件"chip 点了没反应 | 用户天天碰到 | **已修** + 回归测试 |
| 2 | **设置保存会废掉 AI**：GET 把 `apiKey` 掩码成 `******`，前端原样塞进表单，保存时后端 `Object.assign(config.ai, b.ai)` 把假 Key 写回配置，AI 分类全废 | 静默、灾难性 | **已修**（后端识别掩码并忽略 + 前端用独立"留空保持不变"输入框） |
| 3 | **测试套件在 master 是红的**：`diagnostics.test.js` 期望路径穿越返回 403，媒体路由却返回 404（与语音路由不一致） | CI 持续红 | **已修**（403/404 区分 + 回归测试） |
| 4 | **搜索 LIKE 通配符未转义**：用户输入 `100%` 中的 `%` 会退化成全表匹配 | 错检、误检 | **已修**（`ESCAPE '\'` + 转义函数） |
| 5 | **对话框操作静默失败**：`ChannelDialog` 的 `add()` / `login()` / `reLogin()` / `saveRename()` 无 try/catch | 网络抖动 = unhandled rejection，UI 毫无反馈 | **已修**（统一 `run()` 包装 + toast.error） |

## 三、UI 现代化重做要点

### 3.1 设计原则
- **单一强调色**（indigo `#4f46e5`）+ 中性灰阶，靠 1px 描边与留白构建层级，避免重阴影
- **8px 栅格**统一间距；圆角分 6/8/10/14/18 五档；过渡统一 120/180/260ms
- **图标系统**：24×24 描边 SVG，替代原先散落的 emoji（受系统字体影响、跨平台观感差、不可缩放）
- **深浅色双主题**：共用同一组语义变量，组件只引用变量
- **细节**：顶栏毛玻璃（`backdrop-filter`）、品牌色 28px 方块图标、卡片 1px 边框 + 极轻阴影、可折叠分类树、紧凑分段控件

### 3.2 布局

│  ▣ ClawVault  🔍 搜索消息内容…      [通道 22]  ☀  ⚙  ⓘ       │  56px 顶栏（毛玻璃）

### 3.3 关键交互
- **悬停消息卡片**显示删除图标，点击进入"删除这条归档？  删除 取消" 内联确认
- **搜索**：顶栏圆角输入框带清空按钮，300ms 防抖，命中片段黄色背景
- **Toast**：右下角堆叠，3-6 秒自动消失，可手动关
- **设置**：开关 + 输入框混合布局，AI Key 单独输入（"已保存，留空保持不变"占位符）
- **关于**：归档总量 + 品牌色 hero + 4 个外链（仓库 / 更新日志 / 协议 / 隐私）

## 四、版本说明

- 版本号：1.0.25 → 1.0.26
- 依赖：未新增（jimp 早已是 0.22.12）
- 安装方式：与 v1.0.25 相同。fpk 升级为"目录合并"，不会覆盖 data-share 目录
  `/vol1/@appdata/clawvault`（归档数据 / SQLite / 加密密钥 / 持久化设置都安全）
- 强制建议：若从 v1.0.20 之前升级且遇到奇怪问题，可卸载并 `sudo rm -rf /var/apps/clawvault
  /vol1/@appcenter/clawvault` 后离线安装 1.0.26

## 五、未做但值得做的事（留给后续版本）

- **统计仪表盘**：按日 / 周 / 月的归档量趋势、热门分类 Top N、AI 成功率
- **标签与筛选组合**：多选分类、跨通道筛选、按时间范围
- **导出**：单条消息 / 选中多条导出为 JSON / Markdown
- **批量操作**：勾选多条后批量删除 / 批量重新分类
- **i18n**：当前中文硬编码；提取到 `i18n/zh-CN.json` 是低投入高回报
- **PWA / 离线**：把 index.html + 主要 CSS 加 manifest 即可，支持本地 PWA 安装
- **后端测试覆盖率**：当前 70 个用例集中在 storage / ilink / routes_extra，providers/* 缺覆盖
- **无障碍 a11y 完整审计**：aria-live / 键盘导航顺序 / 焦点陷阱（弹窗内 Esc 关闭已加，但环状 tab 未做）
